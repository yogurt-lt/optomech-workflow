# v0.2：减少深筒拧紧，解释清楚调焦，修复显示文件

## 1. 后组三只压圈的取舍

v0.1 是为了独立落座、隔离各组预紧和拆装而作的设计选择，不是必须采用的量产结构。它增加了深处螺纹加工、拧紧工时和工具操作次数，这一例没有充分理由承担这些成本。

[Edmund Optics：Integration of Optical Systems](https://www.edmundoptics.com/knowledge-center/application-notes/optics/integration-of-optical-systems/) 的 Mechanical Integration / Retainer vs. Spacer 介绍了压圈、隔圈及其组合，指出独立沉靠有利于定位控制，而隔圈通常更经济；隔圈堆叠需要处理间隔尺寸链。资料支持这些取舍，不直接证明某个具体尺寸已经合格。

v0.2 改成：**后压圈 → G5 → 厚隔圈45 → G4 → 厚隔圈34 → G3 → 内筒台肩**。后端只拧紧一只压圈。G4/G5 仍有径向定位内孔，但不再分别设置承受轴向预紧的台肩。隔圈落座平面附近的孔径转换提前 0.3 mm，给隔圈与非承压台肩留开间隙，避免锁紧力绕过镜片。实际预紧、接触面应力、尺寸链及必要的选配调整要另行确定。

隔圈34 外径 Φ42，前后端轴向直段各 1.5 mm；隔圈45 外径 Φ46，前后端直段各 1.5 mm。内部让位为锥面，外圆保持简单圆柱。它们传力的端面接触带位于新机械平边，接触带窄不等于整个环体都薄。

## 2. 前隔圈改厚

v0.1 把内外轮廓同时锥化，过度追随镜片口径，形成了薄的平行四边形截面。v0.2 外径保持 Φ42.9，内侧才收口；前后端各留 1 mm 轴向直段，靠 G2 一端显著加厚。内筒配合孔也相应让位，隔圈不被内筒台肩提前挡住。

G5 新参考毛坯半径改为 23 mm（原半径 22 mm），用整圈机械平边形成较宽的后侧接触带。其他镜片机械平边延续 v0.1；原始 ZMX/STP 未修改。光阑仍为 1 mm 平口＋斜面。

## 3. 直槽是否常见；本例具体如何工作

[Konica/Minolta 专利 US3895858A](https://patents.google.com/patent/US3895858A/en) 在图1～3及说明中明确列出导向板5、直导槽4b，让镜框沿光轴移动而不旋转；这是相机镜头中采用直导向止转的直接实例。该专利使用双螺旋结构，与本例的单螺旋＋止推连接不同，不能把整套结构说成相同。

本例的三个运动体：

|部件|连接|运动|
|---|---|---|
|青色固定外壳|连接相机尾卡口，同时提供外螺旋牙和导向孔|不动|
|金色调焦环|内螺旋牙啮合固定外壳的外螺旋牙|旋转，同时轴向移动|
|蓝色光学内筒|前端止推连接跟随调焦环；外周直槽由固定螺钉止转|只平移|

转动金色环时，螺旋副首先产生轴向位移。金色环前端的内伸环形凸缘被“前垫片—凸缘—后垫片”夹持，其前侧有拧在蓝色内筒上的保持环，后侧是蓝色内筒的外伸凸缘。调焦环可以在两垫片之间相对转动，向前或向后移动时则分别通过两侧止推面拉动/推动内筒。这里的“槽”是轴向捕获的环形连接，不是产生行程的凸轮槽。

固定在青色壳上的两枚圆柱端螺钉进入蓝色内筒的轴向直槽：它们阻止内筒跟转，槽端同时限制行程。**螺旋副负责旋转转平移；止推连接负责双向传递平移；直槽负责止转。**

因此你的理解基本正确，需要把“调焦环和外镜筒用槽连接”修正为“调焦环与固定外壳用螺旋牙连接”。0～270° 对应向物方移动 0～4.5 mm；原处方内的镜片和光阑整体移动，内部间距不变。

导向板/平键有相应工业实例；本 demo 的两枚 M3 圆柱端螺钉是一种简化实现，不等于其接触应力、磨损、卡滞和回差已经达到量产要求。工程化可采用有足够接触长度的导向键，并处理双导向的平行度和配合间隙。止推垫片也要确定材料、润滑、轴向游隙和预紧，避免反向调焦出现空行程。

## 4. FreeCAD 空白与 SolidWorks 重开

检查发现 v0.1 交付 FCStd 缺少 `GuiDocument.xml`：无界面校核保存时丢失了显示记录。另有“先保存、后缩放到模型”的顺序问题，会保存过小的相机视野。不能仅凭实体有效就宣称界面显示验证完成。

v0.2 保留原有原生几何，补回组/零件/最终特征的显示记录、颜色及足够覆盖模型的轴测相机。生成宏也改为缩放后再次保存。附 `恢复显示.FCMacro`，在已打开目标模型时运行，可恢复组、Body 和最终特征可见性并缩放到全部。

本地离屏 GUI 在启动时遇到阻塞对话框，因此本轮检查的是原生几何及存档内显示记录的完整性，**实际 FreeCAD 窗口显示仍请你打开确认**。没有把离屏渲染问题当作你电脑的故障原因。

SolidWorks “第一次出问题、再次打开成功”的具体原因尚未确定；没有错误日志，不能归因于某个 API 或模型错误。新版宏仍保存阶段日志，若再次出现可据最后阶段定位。
